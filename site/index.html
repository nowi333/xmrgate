How it works

Up and running in three steps

One small program on your server. One setup screen. Then your shop just gets paid.

Start xmrgate

One command with Docker, HTTPS included: docker compose up -d. Or run the single binary.

Paste two keys

Your wallet address and your secret view key, plus a dashboard password. Your spend key never leaves your wallet.

Connect your site

Install the WooCommerce plugin, drop a payment button on any page, or call the API. Orders confirm themselves.

Your money, untouched

xmrgate only holds a view key. It can see incoming payments and nothing else, so funds can't be stolen through it.

Your key stays home

Public nodes only serve public blocks. Scanning happens locally: nodes never see your key, addresses or payments.

Instant feedback

Customers see "Payment received" seconds after paying, straight from the mempool, before it's even confirmed.

No node to run

Nothing to sync, no blockchain on disk. About 10 MB on disk and 12 MB of memory. Idle when nothing is due.

One address per order

Each invoice gets its own subaddress, so every payment is matched to the right order automatically.

One gateway, many sites

Connect as many websites as you like. Each one has its own secret key and only sees its own payments.

Security model

Built not to trust

  • Nodes are cross-checked. A block is accepted only once a second node reports the same hash. If nodes disagree, xmrgate stops instead of guessing.
  • Unconfirmed is shown, not trusted. Orders are paid after confirmation.
  • Edge cases handled: timelocked outputs are ignored, duplicate output keys counted once.
  • Signed webhooks, HMAC-SHA256, with one key per website.
